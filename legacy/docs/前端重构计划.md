# 前端重构计划（Frontend Refactor Plan）

> 撰写视角：产品经理 / 架构师
> 基线版本：`main @ 3e54b13`（Beta 3 开发中期）
> 日期：2026-06-12

---

## 一、项目全局审阅结论

当前系统为 Flask 后端 + 纯静态前端（`static/`）的单体应用。后端已完成蓝图化拆分
（10 个 routes 蓝图 + 17 个 services），结构尚可；**前端是当前最大的工程债务集中区**：

- `static/js` 及 HTML 合计约 **49,000 行**手写代码，无模块系统、无构建、无测试；
- `static/index.html` 单文件 **5,877 行**（HTML + 内联 CSS + 模板混杂）；
- `admin.js` **7,562 行**、`student.js` **5,679 行**，均为单文件巨石；
- 10 个 `<script>` 标签按顺序加载，跨文件通过隐式全局变量（`window.*`、顶层
  `let/const`）耦合，`elements.js` 集中持有数百个顶层 DOM 引用，`state.js`
  为全局可变状态——任何文件都可读写任何状态，不可单测、不可静态分析；
- `foreign-trade/` 虽已搭好 Vite + React 19 + TS 脚手架，但仍是未改动的
  counter demo，与主应用零集成。

- 富文本（Quill）、语音（WebSocket ASR/TTS）、SSE 流式评估等强交互模块缺乏边界封装，是迁移中的高危区。

## 三、重构目标与原则

**产品目标**：在不中断 Beta 3 迭代的前提下，把前端迁移到可控的现代化架构，使
"新增一个教师工作台模块"的成本从"在 7,600 行文件里找位置"降为"新建一个目录"。

**架构原则**：

1. **绞杀者模式（Strangler Fig），不做大爆炸重写**。旧版 `static/` 持续可用，
   新版按页面/域逐块替换，每个阶段都可发布、可回滚。
2. **先止血，再建设，后迁移**。P0 问题不依赖任何新架构，立即处理。
3. **服务端状态与客户端状态分离**。API 数据交给数据获取层管理（缓存/重试/失效），
   组件内只保留 UI 状态，杜绝再造一个全局 `state.js`。
4. **强交互模块（语音通话、SSE 评估流、Quill 富文本、G6 图谱）先封装后迁移**，
   以适配层隔离第三方库。

## 四、技术选型（决策与理由）

| 关注点 | 选型 | 理由 |
|--------|------|------|
| 框架/构建 | **React 19 + TypeScript + Vite 7**（复用 `foreign-trade/` 脚手架，目录更名为 `frontend/`） | 选型已由现有脚手架确定，不再摇摆；TS 是治理 5 万行无类型代码的核心手段 |
| 路由 | React Router | 学生端/教师端双入口，路由级代码分割 |
| 服务端状态 | TanStack Query | 取代散落各处的 `fetchWithAuth` + 手动刷新；自带缓存、加载/错误态 |
| 客户端状态 | Zustand（仅 auth、当前会话等少量全局） | 轻量、可测试，避免重蹈全局 `state.js` 覆辙 |
| 样式 | Tailwind CSS v4（npm 安装，替代 CDN） | 现有 HTML 已全面使用 Tailwind 类名，迁移成本最低 |
| 图表 | **收敛为 ECharts**（折线/趋势，替代 Chart.js）+ **G6**（知识图谱，保留） | 从 3 个库减为 2 个；Chart.js 用法最浅、最易替换 |
| 富文本 | Quill 2（npm 化，封装为受控组件） | 已有大量自定义 blot 投入，不更换 |
| API 层 | 统一 typed client（手写 `api/` 模块 + 共享类型；后端补 OpenAPI 后可代码生成） | 当前 22 行的 `api.js` 之外散落着上百处裸 fetch |
| 测试 | Vitest + Testing Library（单元/组件）+ Playwright（学生练习、教师批改两条冒烟链路） | 迁移期间的安全网 |
| 质量门禁 | ESLint + Prettier + CI（lint/typecheck/test/build 必过） | 脚手架已含 ESLint 9，补 CI 即可 |

**与 Flask 的集成方式**：开发期 Vite dev server 以 proxy 转发 `/api`、`/ws` 到
Flask；生产 `vite build` 输出到 `static/dist/`，Flask 新增 `/app` 路由托管新版
入口，旧版 `/` 不动——这是绞杀者模式的物理基础。

## 五、分阶段实施计划

### Phase 0：止血（≈1 周，不依赖新架构，可立即执行）

- [x] 删除 5 个 `* 2.*` / `* 3.*` 残留文件（git 历史中可随时找回）；
- [x] 处置 `static/js/admin/` 死代码：经核实该目录自 2025-11-29 后未再更新且无任何 HTML 引用（`admin.js` 持续维护至 2025-12-29），已删除，并修正 CHANGELOG/BETA2 文档中"已拆分 8 模块"的失实描述；
- [x] 消除 CDN 运行时依赖（方案升级：不止锁版本+SRI，而是将 Chart.js/marked/DOMPurify/Quill/ECharts/G6 六个库从 npm 官方 tarball 提取后本地托管于 `static/vendor/`，`marked`/`echarts` 锁定为原 CDN 实际解析版本 18.0.5/5.6.0；Tailwind Play CDN 无 npm 等价物，锁定为 3.4.17，Phase 1 npm 化后移除）；
- [x] 清理 `.gitignore`（去重、移除对 `.gitignore` 自身的错误忽略）并删除已入库的 `.DS_Store`；
- [ ] 为旧版关键链路录制 Playwright 冒烟用例（登录→选关→对话→评估；教师查看学生会话），作为后续所有迁移的回归基线。**依赖可运行环境（DeepSeek/DashScope 密钥、Neo4j），需在本地/CI 环境补做。**

**退出标准**：仓库无重复/死文件；CI 跑通冒烟用例。

### Phase 1：新工程地基（≈1–2 周）

- [ ] `foreign-trade/` 更名为 `frontend/`，清掉 demo 代码，建立目录骨架：
  ```
  frontend/src/
    api/          # typed client + 各域 API 模块
    stores/       # auth 等少量全局状态
    features/
      student/    # 学生端各功能域
      admin/      # 教师工作台各功能域
    components/   # 通用组件（按钮、弹窗、表格…）
    lib/          # SSE、WebSocket 音频、Quill、G6 适配层
  ```
- [ ] 实现 auth（登录、token 刷新、401 统一处理）、整体布局与路由；
- [ ] Vite proxy + Flask `/app` 托管打通，部署脚本纳入 `npm run build`；
- [ ] CI：lint + typecheck + test + build 四道门禁。

**退出标准**：用新架构上线第一个真实页面（建议：教师端"学生列表"，逻辑简单、内部用户容错高）。

### Phase 2：按域垂直迁移（≈6–8 周，可与业务迭代并行）

迁移顺序按"风险递增"排列，每个域迁完即在新版入口可用、旧版对应入口下线：

| 批次 | 域 | 对应旧代码 | 难点 |
|------|----|-----------|------|
| 2.1 | 教师端：学生管理、作业、蓝图 | `admin.js` 约 1/3 | CRUD 为主，验证架构 |
| 2.2 | 教师端：关卡编辑、理论课（Quill） | `admin.js` 其余 + 自定义 blots | Quill 受控组件封装 |
| 2.3 | 教师端：知识图谱（G6） | `graph-knowledge.js`、`graph-transformer.js` | G6 适配层、大数据量渲染（顺带解决 TODO 中的性能项） |
| 2.4 | 学生端：首页、理论学习 | `student.js` 部分 | 低风险 |
| 2.5 | 学生端：实战练习（聊天、邮件、Copilot、SSE 评估流） | `student.js` + `main.js` | SSE 流式渲染、知识点状态提示 |
| 2.6 | 学生端：语音通话（WebSocket ASR/TTS、PCM 音频） | `student.js` 语音部分 | 最高风险，放最后；`lib/` 中先做音频管线适配层并独立联调 |

**节奏要求**：每批次一个 PR 系列，附 Playwright 用例更新；新旧两版在迁移期并存，
出问题可一键切回旧入口。**冻结旧代码**：Phase 2 启动后 `static/js` 只接受 bugfix，
新功能一律进 `frontend/`。

### Phase 3：收尾与下线（≈1–2 周）

- [ ] 删除 `static/js/`、`static/index.html` 及全部 CDN script 标签，`/` 切到新版；
- [ ] 性能基线：路由级代码分割、图表库按需加载、首屏 < 2s（局域网）；
- [ ] 测试覆盖率门槛（建议语句覆盖 ≥ 60% 起步）；
- [ ] 更新 README / 部署文档 / 开发者上手指南。

## 六、风险与对策

| 风险 | 对策 |
|------|------|
| 双栈期新旧功能重复开发，拉长迁移周期 | 旧代码冻结策略 + 每批次明确下线旧入口，不允许"两边都维护" |
| 语音/SSE 迁移引入难以排查的实时性 bug | 适配层先行、独立联调页验证后再接入业务；该批次安排在最后 |
| 无测试基线导致迁移回归不可知 | Phase 0 即建立 Playwright 冒烟链路，作为每个 PR 的硬门禁 |
| 团队对 React/TS 熟悉度参差 | 2.1 批次刻意选最简单的 CRUD 域作为脚手架范例（feature 目录即模板） |
| 后端无 OpenAPI，类型靠手写易漂移 | 短期手写共享类型；中期给 Flask 蓝图补 OpenAPI 注解后切换为代码生成 |

## 七、度量指标（用于汇报与验收）

- `static/js` 剩余行数（目标：Phase 3 末归零，当前约 49,000 行含死代码）；
- 新版 bundle 体积与首屏时间；
- 前端 CI 通过率、测试覆盖率；
- 迁移后 30 天内各域回归缺陷数（对比迁移前同期）。

---

**一句话总结**：先用一周清掉重复文件、死代码和 CDN 隐患（P0），随后以现有
React 脚手架为地基，按"教师端 CRUD → 富文本/图谱 → 学生端 → 语音"的风险递增
顺序做绞杀式迁移，全程旧版可回滚、新功能只进新栈，预计 10–13 周完成切换。
