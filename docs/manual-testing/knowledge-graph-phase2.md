# 知识图谱 Phase 2 手工验收指南

## 1. 本工单解决的用户问题

让教师编写的教学案例不止生成一张图，而是真正驱动学生训练中的局面识别与渐进脚手架，并让教师从训练证据回看薄弱现象、知识和策略。

## 2. 范围与非范围

范围内：全 20 关教师 DSL、正式 Neo4j 发布、Attempt 图谱版本绑定、场景/对话 Agent 上下文、学生分级脚手架、提示使用记录、逐轮学情证据、教师班级/学生洞察、回放证据和 Cytoscape.js 图谱。

明确不做：学生端全局大图、自动教材抽取、LLM 自动发布关系、复杂图算法、三维图谱和在线本体编辑器。

## 3. 环境准备

在根目录 `.env` 设置 `KNOWLEDGE_GRAPH_PROVIDER=neo4j` 与完整 `NEO4J_*` 配置。`compose.yaml` 默认将 Neo4j HTTP/Bolt 映射到 `17474/17687`，认证密码必须与 `.env` 一致。

```bash
docker-compose up -d neo4j
pnpm db:migrate
pnpm seed:users
pnpm seed:curriculum
pnpm seed:classroom
pnpm dev:api
```

另开终端：

```bash
pnpm dev:web
```

开发账号密码由 `DEV_SEED_PASSWORD` 配置；不得把密码或 API Key 写进文档、截图和日志。

## 4. 自动冒烟测试

```bash
pnpm smoke:neo4j-phase2
```

该命令使用真实应用 API 完成教师上传、提交评审、技术员批准、Neo4j 发布和教师图谱读取。完整工作簿应编译出 20 个案例、439 个内部节点和 440 条内部关系；教师投影视图应为 200 个节点和 160 条关系，其中包含 40 个现象、80 个知识资源和 80 个策略战术。

## 5. 手工验收路径

### 技术员与教师发布

1. 教师/技术员上传 `content/knowledge-graph/templates/teacher-case-dsl-v1.xlsx`。
2. 确认 20 个案例覆盖课程全部 20 关，且校验没有阻断项。
3. 教师提交评审，技术员批准并发布。
4. 确认活动版本后端为 `neo4j`；重复发布不产生重复版本。
5. 模拟 Neo4j 不可用时，发布应返回可重试的明确错误，现有活动版本不受影响。

### 学生训练消费

1. 新建一次训练，确认 Attempt 固定记录活动图谱版本。
2. 场景刷新后保持不变；学生端只显示当前局面、知识资源名称和渐进提示，不泄露完整标准策略。
3. 展开一级提示，再标记“已采用”；刷新后两种状态均恢复。
4. 发送一轮消息后，确认逐轮评价仍返回分数、Pros、Cons、详细评价、下一步建议与自查项，同时生成图谱学情证据。
5. 发布新图谱后回到旧 Attempt，确认其仍读取原绑定版本。

### 教师学情与图谱

1. 班级总览的“知识图谱学情”完成数和平均分应与当前课程版本一致，历史课程同名关卡不得重复计数。
2. 学生详情展示薄弱关卡及其关联现象、知识资源、策略和脚手架使用统计。
3. 训练回放展示图谱版本、每轮关联节点和映射方式。
4. 打开 `/teacher/knowledge-graph`，确认可搜索、按三类节点筛选、缩放、适应画布并点击节点查看直接邻居。

## 6. 验收标准

- Neo4j 健康，活动图谱可从真实驱动读取。
- 全量教师 DSL 的“知识资源 + 策略战术”为 160，超过 100 节点要求。
- 学生至少完成一次提示展开和采用，事件可恢复且幂等。
- 图谱上下文进入 Agent，但权限、Attempt 完成和进度仍由确定性业务规则决定。
- 教师学情只统计其有权访问的学生和相应课程版本。
- `pnpm check` 与 `pnpm smoke:neo4j-phase2` 全部通过。

## 7. 风险与回滚

- Neo4j 故障：API 返回 `knowledge_graph.storage_unavailable`，训练保留原课程数据并给出明确降级/重试反馈。
- 发布失败：新版本保持未激活，上一活动版本继续服务。
- 内容错误：回滚活动 Publication，旧 Attempt 仍按已绑定版本复盘。
- 教学价值不足：关闭教师大图入口，但保留局部脚手架和结构化学情证据，不影响基础谈判闭环。
