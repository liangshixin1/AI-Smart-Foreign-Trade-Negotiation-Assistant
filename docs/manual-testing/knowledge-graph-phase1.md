# 知识图谱 Phase 1 手工验收指南

> 本文是关系型演示发布阶段的历史基线。当前系统已进入正式 Neo4j 与训练消费的 Phase 2；新验收请使用 [Phase 2 指南](./knowledge-graph-phase2.md)。

## 验收前准备

```bash
pnpm db:migrate
pnpm dev:api
```

在另一个终端启动 Web：

```bash
pnpm dev:web
```

使用技术员账号登录 `http://127.0.0.1:5174/technician`。开发环境默认账号为 `technician@example.test`，密码取自 `.env` 的 `DEV_SEED_PASSWORD`。

## 最小演示闭环

1. 点击“下载 DSL 1.0 模板”，确认获得 `.xlsx` 文件。
2. 在“选择教学案例表”中上传 [Phase 1 示例表](../../content/knowledge-graph/templates/teacher-case-dsl-v1.xlsx)。
3. 期望显示：`0` 个阻断、`3` 个警告。三个警告均是“局面尚未配置分级提示”，不阻止评审。
4. 确认变更集摘要为：`4` 个教学案例、`71` 个语义节点、`69` 条可追溯关系、`0` 个冲突。
5. 切换四个案例，检查关键局面、应对策略、脚手架与知识、评价维度和条件化结果是否符合教学意图。
6. 依次点击“确认教学链并提交评审”、“批准变更集”、“发布至隔离演示环境”。
7. 期望页面显示一个 `demo-*` 激活版本，存储后端为 `relational_demo`。
8. 点击“回滚演示版本”，确认激活版本消失，变更集回到“已批准，待发布”。

## 错误体验检查

- 清空任一带“必填”的教学内容单元格后再上传，页面应指出工作表、行号和列名，不生成变更集。
- 重复上传同一文件，页面应恢复原导入结果，不重复创建任务。
- 学生角色调用模板或导入 API 应返回 `403`；教师可上传自己的工作簿，但不能批准或发布。

## Phase 1 边界

本阶段用隔离的关系型存储保存完整节点和关系载荷，用于演示审批、版本和回滚语义。它不写入 Neo4j 正式库，不向学生训练流程注入图谱内容，不执行 LLM 自动建边。
