# 风险、迁移回滚与阶段验收

## 1. 迁移策略

这里不存在可审计的旧应用或旧数据库，因此 P0 不是“原系统原地升级”，而是两条彼此隔离的迁移：

1. **教学资产迁移**：从固定哈希的 `levels.py` 解析 20 小节，生成草稿 YAML；经自动校验和教学审校后发布为不可变课程版本。
2. **新系统上线**：新建应用、数据库和身份/班级数据，不假设旧数据表或 API 兼容。

### 1.1 教学资产迁移步骤

1. 把源文件哈希、迁移器版本和执行人写入迁移报告。
2. 解析章节、小节、公开场景、场景简报、actor 脚本、评价意图和锁定事实。
3. 生成课程、模板、提示词和量规草稿，不直接发布。
4. 运行 ID/引用/变量/Schema/隐藏字段/贯穿事实校验。
5. 教学负责人审校三种模式映射、先修、时长、专业知识和量规权重。
6. 生成 manifest 和内容哈希，发布 `CourseVersion 1.0.0`。
7. 任何修订创建新版本；已开始 Attempt 永远使用其绑定版本。

### 1.2 数据迁移边界

阶段 0 没有收到学生、教师、班级、历史训练或评价数据，不能设计“旧数据导入已完成”。若后续提供旧数据，必须另开迁移工单：先做字段画像、质量报告、身份匹配、试迁移、对账和回滚演练。

## 2. 回滚策略

| 变更类型    | 前向策略                       | 回滚方式                                             |
| ----------- | ------------------------------ | ---------------------------------------------------- |
| 课程内容    | 发布新不可变版本               | 停止把新版本分配给新班级；旧 Attempt 不受影响        |
| 提示词/量规 | 新版本替代，不原地改           | 激活上一已验证版本；已生成证据保留原绑定             |
| Agent 配置  | 测试后原子激活                 | 激活上一配置版本；密钥按独立流程轮换                 |
| 数据库      | Alembic expand/contract        | 发布前做备份；优先应用前向修复；破坏性收缩需独立窗口 |
| API         | `/api/v1` 内只做兼容扩展       | 回滚应用版本；数据库扩展字段保持兼容                 |
| Web         | 静态版本化发布                 | 切回上一构建产物；服务端保持兼容窗口                 |
| 异步 Worker | 任务 payload 带 schema version | 停止新 worker、排空/隔离不兼容任务、恢复上一 worker  |

禁止把 Alembic downgrade 当作默认生产回滚手段。涉及数据删除或不可逆变换时，必须采用 expand → 双读/回填 → 验证 → contract，并在 contract 前保留可恢复备份。

## 4. 分阶段路线与验收门

### 阶段 1：工程骨架

范围：

- Vue 3 + TypeScript strict + Vite + Router + Pinia。
- FastAPI + Pydantic + SQLAlchemy + Alembic。
- ESLint、Prettier、文件行数、后端 lint/type/test、CI。
- 统一错误格式、健康检查、配置加载、去敏日志。
- User/Role 最小模型，学生/教师/技术员登录与 API RBAC。

门禁：

- 三个角色可登录到各自占位工作区；错误角色访问接口返回 403。
- 密码不明文存储，登录失败不暴露账号是否存在。
- OpenAPI 可生成；Web 类型检查、lint、unit build 通过；API lint/type/test 通过。
- Alembic 能从空库升级到最新；应用启动不发起 LLM 或重型初始化。

### 阶段 2：单条纵向切片

对象：`chapter-3-section-1`。

范围：路线显示 → 准备 → 场景生成 → 对话 → 自动保存 → 确认提交 → 结构化评价 → 进度 → 教师回放。

门禁：

- 三个 Agent 使用三个独立用途配置和密钥引用。
- 场景快照刷新不变；学生消息在 AI 失败时不丢失。
- 提交幂等且冻结；评价证据精确匹配；失败可重试。
- 学生路线只在成功完成后更新；教师能从分数下钻到证据和版本。
- 关键 E2E 在 mock provider 下稳定通过；真实 provider 另做受控 smoke test。

### 阶段 3：迁移全部当前路线

范围：迁移当前可证实的 20 小节，并补齐邮件、单证审阅工作台。若届时取得 34 小节权威源，以新迁移差异工单处理。

门禁：

- 20/20 内容通过 ID、引用、变量、Schema、隐藏字段和贯穿事实校验。
- `chapter-0-section-1` 邮件模式和 `chapter-6-section-1` 单证审阅模式通过模式验收。
- 每节绑定明确量规；无未发布引用；无手工复制后未测试内容。

### 阶段 4：教师跟踪能力

范围：班级总览、筛选、详情、回放、薄弱聚合和四类风险规则。

门禁：

- 所有指标有定义、时间窗口和样本数。
- 所有风险标签有原因；所有薄弱维度可追溯到证据。
- IDOR/越权测试覆盖班级、学生和 Attempt。

### 阶段 5：稳定性与体验

范围：慢网/断线、超时、限流、恢复、性能、无障碍、完整 E2E、部署/备份/恢复文档。

门禁：

- 关键流程在网络抖动和重复请求下不丢事实、不重复完成、不重复计费。
- 常见笔记本无横向滚动；键盘主流程可完成；移动端学生主流程可用。
- 备份恢复与发布回滚演练有真实记录。

## 5. 质量门槛

### 后端必须覆盖

- 三角色认证、权限和越权访问。
- Attempt 所有合法/非法状态转换。
- 创建、消息、提交、评价、重练的幂等。
- 场景失败、对话失败、评价 Schema/证据失败和显式重试。
- 进度只投影成功完成事实。
- 课程发布不可变与版本追溯。
- 日志、错误和学生 API 不泄漏密钥/底牌/完整敏感上下文。

### 前端必须覆盖

- 路由权限与工作区切换。
- 路线状态、创建/恢复、三种模式注册。
- SSE 顺序、断线续传、重复 delta 去重和最终资源校正。
- 自动保存冲突、提交确认、提交防重复、评价失败重试。
- 教师筛选、风险原因、学生详情与证据回放。
- 加载、空、错误、慢网络和键盘操作。

### 端到端闭环

学生登录 → 选择 3-1 → 生成场景 → 多轮交互 → 明确提交 → 评价完成 → 路线完成 → 教师登录 → 找到学生 → 打开完整回放。该闭环未通过前，不启动 P1/P2 产品功能。

## 7. 自动推进时采用的决策记录

用户已授权审计后按本路线自动开发，因此阶段 1 采用：

- 当前 20 小节为首个权威课程范围；保留未来追加内容的版本机制。
- 接受三模式语义映射与 `[standard]` 单难度基线。
- 接受每 Attempt 一次生成并固化场景快照。
- 接受 `chapter-3-section-1` 作为纵向切片。
- `retry_created` 在阶段 1 先作为审计事件设计，原 Attempt 保持 `completed`；这样完成事实不被状态字符串覆盖。若后续必须严格使用状态枚举，再通过 ADR 调整。
- provider/model/key 采用配置边界；没有真实凭据时只运行 mock provider 测试，不宣称真实模型连通。
