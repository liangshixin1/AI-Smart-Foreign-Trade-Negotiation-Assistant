# 教师端知识图谱初始化现状与问题分析

## 现状概览

- 教师首次打开知识图谱页面时看到的分类树与知识点列表，来自应用启动阶段自动写入 Neo4j 的预置数据。
- Flask 应用在创建实例时会调用 `graph_service.bootstrap_graph()`，从而执行静态内容的同步流程，让教师在未上传任何理论知识时也能浏览基础结构。

## 预置数据来源

### 知识分类树

- 迁移脚本 `migrations/001_enhance_knowledge_graph.py` 中定义的 `DEFAULT_CATEGORIES` 提供了 5 个一级类目以及相应的二级类目。
- 迁移执行时，这些节点被写入 Neo4j，构成教师端初始的分类树。

### 知识点列表

- 预设知识点名称集中定义在 `SECTION_KNOWLEDGE_PRESETS` 常量中，覆盖不同实训章节的关键知识点。
- 应用启动后，`sync_static_content()` 会遍历章节与练习，调用 `_ensure_practice_knowledge()` -> `_set_practice_knowledge_tx()`，基于这些名称 MERGE 出 `KnowledgePoint` 节点并建立练习与知识点的 `TESTS` 关系。

### 前端数据获取

- 教师端页面通过 `/api/graph/knowledge-points/overview` 调用后端的 `get_knowledge_management_overview()`。
- 该函数将 Neo4j 中的知识点、分类路径与统计信息聚合后返回给前端用于渲染。

## 发现的问题

1. **预置结构与真实课程可能脱节**
   - 自动写入的分类树与实际教学大纲不一定一致，教师难以区分系统默认与自定义内容。
2. **默认知识点缺乏上下文说明**
   - 练习会自动关联到默认知识点，教师若要替换或删除需要额外操作，容易误解为系统推荐或强制项。
3. **自定义空间界限不清晰**
   - 分类结构硬编码于迁移脚本，前端未标识默认与自定义节点差异，教师担心修改会被覆盖或与既有体系冲突。
4. **对学生学习体验的潜在影响**
   - 学生可能看到尚无理论内容支撑的知识点标签，导致学习路径断层。
   - 默认节点计入统计可能误导教师和学生对学习进度与薄弱点的判断。
5. **运营与维护成本**
   - 多学校适配需改动代码或迁移脚本，缺乏配置化手段。
   - 更新预置清单时历史环境可能遗留旧节点，造成数据混杂。

## 后续建议（方向性）

- 在教师端明确标识系统默认数据与用户自定义数据的差异，并提供引导说明。
- 提供配置化入口或初始化脚本，方便按学校或课程定制分类与知识点。
- 考虑在首次登录时提示教师确认或调整默认结构，避免混淆。
- 建立预置数据版本管理与清理机制，减少后续迁移的“脏数据”。
