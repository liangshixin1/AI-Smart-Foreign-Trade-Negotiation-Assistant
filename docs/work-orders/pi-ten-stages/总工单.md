2. 数据：深拷贝归一化源行，更新阶段中英名称、描述、OBE、现象主归属、知识主归属、边和衍生索引；持久化十阶段快照及翻译覆盖。禁止就地修改旧发布快照。
3. 发布迁移：从当前活动版本的原始工作簿生成新变更集；备份数据库；复用已有发布/审计/回滚机制；拒绝未知源版本。只复制身份和语义仍一致的教师内容、媒体与显示覆盖；合并阶段 S9 的旧内容不自动归入任一新阶段，保留旧版本并在报告列出。
4. 历史：旧 Attempt.content_bindings、GraphLearningEvidence、KnowledgeLearningActivity 仍引用旧版本；不得将旧完成记录伪造为新版本已完成。新训练读取新活动版本。
5. 前端：取消九阶段固定文案；教学蛇形布局扩展到任意行，防止第十阶段落入旧第五阶段坐标；全景/流程边依真实 Seq 排序，测试 S10 数值排序。
6. 管理：界面明确源表为原始表、导入生成十阶段版本，默认使用 3.1；保留原有角色权限和评审发布流程。
7. QA：源变换不变性、分配/计数、幂等、快照与图一致、媒体复制/合并阶段排除、旧回放、回滚；前后端 lint/typecheck/tests/build；本地真实 Neo4j 发布与浏览器核查。

## 风险与回退

- S9 旧合并语义与新投诉语义不同：所有读取必须使用 graph_version + node_key，不能只按 S9 覆盖旧内容。
- 图谱变化不等于课程进度清零：保留课程版本与单元，不重建学生或班级。
- SQL 与 Neo4j 是两个存储：发布前验证，发生失败不得把新版本报告为已激活；回滚通过原发布服务恢复前一图版本，保留审计。
- 备份含原有用户数据，只放本机不提交；QA 报告不包含账号口令和学生内容。
- 只有实际执行且有证据的项目可标记通过；自动化验证与真实浏览器验证分开记录。

## 实施交付与操作手册

|工项|实现位置|完成标准|
|---|---|---|
|十阶段业务契约|`pi_stages.py`|固定中英名称、稳定编号、投诉/索赔分配、衍生计数|
|导入兼容|`import_service.py`、`v3_compiler.py`|3.1 使用显式转换；3.0 原行为测试保留|
|关系数据库快照|`repository.py`|编译与持久化使用同一归一化数据和场景集合|
|版本发布与内容继承|`pi_migration.py`、`review_service.py`|旧发布保留，SQL 提交失败恢复旧图；审计记录来源与跳过项|
|本地迁移|`scripts/migrate_pi_stages.py`|仅本地 development/SQLite，先健康检查和备份再发布|
|现场检查|`scripts/qa_pi_stages.py`|只读比较 SQL/Neo4j、名称顺序、归属、悬空边|
|地图布局|`graphPresentation.ts`|蛇形布局扩展，S10 与 S1–S9 不重叠|
|管理界面|`knowledgeGraphApi.ts`、`KnowledgeGraphImportPanel.vue`|默认十阶段转换并说明原始源表身份|
|测试|`test_pi_stages.py`、`piStages.test.ts`|历史隔离、继承、幂等、回滚、失败恢复、S10 顺序|

完整路径分别位于 `apps/api/app/modules/knowledge_graph/` 与 `apps/web/src/features/knowledge-graph/`；管理界面位于 `apps/web/src/features/technician/`。

运行目录：项目根目录。

```sh
# 预检（只读）
PYTHONPATH=apps/api .venv/bin/python scripts/migrate_pi_stages.py
# 已授权的本地迁移；自动备份，重复执行不新增活动版本
PYTHONPATH=apps/api .venv/bin/python scripts/migrate_pi_stages.py --apply
# 只读现场 QA
PYTHONPATH=apps/api .venv/bin/python scripts/qa_pi_stages.py
```

回滚：技术员通过现有发布管理执行当前版本回滚，接口为 `POST /api/v1/knowledge-graph/publications/{publication_id}/rollback`。这会恢复前一版本并保留新旧发布及审计，不要直接覆盖数据库备份来回退日常业务。备份恢复只用于数据库灾难恢复，并需处理备份后新增业务记录。

本次不需要新增 Alembic 表结构：阶段数量和编号已由版本化行及 JSON 图负载承载，无数据库“只能九阶段”的 DDL 约束。通过业务数据迁移生成新快照比原地改旧行更适合历史回放。

源证据口径：原始 XLSX 二进制和原始二维工作表仍保存原貌；新快照的行哈希针对归一化后的行，结合原文件 SHA256、源行号及 `expert-pi-compiler/3.1.0` 追溯。新增 S10 的源行号为 0，表示由转换生成，不冒充专家源表已有行。
