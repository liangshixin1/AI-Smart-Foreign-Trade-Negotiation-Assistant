## 1. 产品审评：建议立项，定位为“可交互的商务情境剧”

### 1.1 为什么适合本项目

- 固定立绘、有限表情、简短台词与情境反馈，能让学生感受到对方在回应自己的选择，制作与维护量可控。
- 实战仍由学生自由表达驱动，知识支持与教师证据链继续复用，不把专业训练变成选答案游戏。
- 先文字、后 TTS/ASR 的顺序合理：先验证台词节奏、状态解释和教学闭环，再承担语音延迟、转写误差及设备权限的复杂性。
- “寓教于乐”具体体现为可感知的局面变化、角色反应、一次一事的节奏、可复盘的选择后果；不以积分商城、打卡奖励或长篇剧情充当趣味。

### 1.2 对原设想的四项修正

| 原设想 | 产品决策 | 原因 |
| --- | --- | --- |
| 类似好感度 | 学生可见的“谈判态势”：沟通信任、合作意愿、条款共识 | 避免把礼貌迎合等同于商业能力；仍保留局势变化的游戏感 |
| 数值决定进度 | 态势影响下一轮谈判风格；任务进度由证据里程碑决定 | 角色开心不能自动通关，专业拒绝也不能自动判失败 |
| 台词精简 | 对手每轮 1–3 个短句，总长有服务端硬约束 | 不是在客户端把旧长回复切碎，必须改变生成与评价方式 |
| AVG 简报独白 | 公共事实驱动的叙事分镜，与原场景快照一致 | 避免艺术化介绍擅自增加价格、期限、角色动机或泄露底线 |

### 1.3 三种结果必须分开

1. **谈判态势**：本局动态估计，帮助学生理解局面；不是真实心理测量，也不是正式成绩。
2. **商业结果**：达成模拟协议、暂未达成、决定暂缓；用条款和双方表达说明，不用“角色喜欢你”判断。
3. **学习结果**：正式提交后的既有评价与进度规则。学生坚持合理底线而未成交，也可能获得很好的学习评价。

所有数值初值、阈值、长度和性能预算都是本 MVP 的待校准产品配置，不是经实验验证的心理学或教学结论。

## 3. MVP 范围与边界

### 3.1 本轮必须交付

- 原 IM 模式可继续使用；支持在符合条件的新训练开始前选择“对话模式 / 仿真模式”。
- 一个完整可玩的代表性关卡：优先 `chapter-3-section-1`（首次还盘）。若实际发布数据不适用，选择另一个 negotiation 关卡并书面说明；不绕过先修规则。
- 一个与剧本身份一致的成年商务对手、一个固定会谈场景、5 种固定表情、3 种轻动作。
- 叙事式简报：逐句播放、即时显示、下一句、跳过演出查看摘要、重看。
- AVG 对话舞台：立绘、头像、角色名、逐句打字机、自由文本输入、历史记录。
- 学生可见的三维谈判态势与任务里程碑；每次变化可追溯到本轮证据。
- 原有知识图谱、目标清单、提示揭示/采用记录与逐轮诊断接入。
- 自动保存、刷新恢复、断线重试、正式提交、评价、教师回放闭环。
- 功能开关、资产降级、已有 Attempt 兼容、桌面及手机适配。
- mock 自动测试、真实模型受控联调、浏览器 QA、最终验收记录。

### 3.2 明确不进入 MVP

- 三维、Live2D、骨骼动画、实时口型、实时生成立绘、物理动作引擎。
- 多角色轮流加入、分支剧情树编辑器、角色养成、恋爱关系、货币/商城/排行榜。
- 替学生生成完整最佳答案的按钮；多项选择可作为以后辅助，当前仍以自由表达训练为主。
- TTS、ASR、麦克风权限、音频上传或隐藏的浏览器语音试接。
- 新的商业报价计算平台或通用交易引擎；只实现代表关卡必要的条款账本与校验。
- 全部课程批量改编。一个闭环验收后，再扩至相邻 2–3 个 negotiation 关卡。
- 根据角色设定重新划分真实学生风险、修改成绩体系、强制学生使用仿真。

### 3.3 资产依赖与完成状态

开发可先使用本地中性剪影和占位背景，让工程闭环先跑通。没有底图不应阻塞 Schema、UI 播放器、规则和 mock 测试。

但“带最终二次元角色的 MVP 已验收”必须具备用户底图、实际生成的表情/动作资产、角色一致性检查和人工审美验收。未具备时只能交付“功能 MVP 已跑通，正式资产待接入”。任何时候不得冒称已调用 ImageGen 或已获得用户美术认可。

## 4. 体验设计与学习节奏

### 4.1 入口与模式稳定性

- 准备页在难度旁提供两个简短选项：对话模式；仿真模式（情境演出与简短交锋）。服务端返回支持的模式，不由前端硬编码全部可用。
- 创建时写入 `experience_mode = chat | simulation`，默认 chat；本 Attempt 内不可修改。
- 仿真内“查看文字记录”只切换展示视图，不把对话策略切回长函电，不新建 Attempt，不丢草稿。
- 历史 IM Attempt 不自动变成仿真；要体验另一模式时新建重练，保留 retry 关联、先修和权限规则。
- 正式历史和教师回放显示模式标签，保证分数和证据的解释语境。

### 4.2 叙事简报

一次简报 4–7 个分镜，每个分镜 1 个句意、1–2 行主体文字。默认中文叙述，角色交易发言默认英文。

建议结构：地点与当下 → 我的身份 → 对方与标的 → 公开条款 → 当前分歧 → 本次目标 → 对手开场。

以第一/第二人称的现场讲述代替表格逐字段朗读。例如：“你把报价单放回桌面。今天要谈的，是这批显示模组的价格。”具体数字由已绑定公共事实插入。旁白不能把学生未作出的选择叙述成事实，不能出现“我已经决定接受”。

- “跳过演出”立即进入常驻摘要，保留全部任务与关键条款；不强制观看动画才允许训练。
- 后续从工具栏重看简报，不再次调用模型，不改写原场景，不重复加入开场 Message。
- 旁白不是学生/对手发言，不进入正式对话计分。开场白是第一条真实 assistant Message，只保存一次。
- 缺少演出数据时显示规范化原始公共简报；不能为了保持演出强行补造交易事实。

### 4.3 舞台布局

桌面示意：

```text
[返回路线] [本节标题 / 已保存]             [简报] [历史] [学习支持] [正式提交]
[沟通信任  ▰▰▰] [合作意愿 ▰▰▱] [条款共识 1/3] [本节目标 1/3]
┌─────────────────────────────────────────┬──────────────────┐
│ 固定商务背景 + 对手立绘                   │ 学习支持（可收起）│
│                                         │ 目标 / 图谱 / 提示 │
│ [头像] David Lim                         │                  │
│ “A lower price needs a stronger order.”  │                  │
│                           [立即显示/下一句]                  │
├─────────────────────────────────────────┴──────────────────┤
│ 你的回复 [自由输入……………………]               [发送]          │
└────────────────────────────────────────────────────────────┘
```

手机示意：

```text
顶栏：退出 · 小节名 · 保存状态
态势：三项紧凑指标 + 可展开解释
舞台：对手半身立绘（有限高度）
对话框：头像、姓名、当前句、下一句
输入：自由文本与发送
工具：简报 / 历史 / 支持 / 提交（不得被键盘遮挡）
```

- 优先可读性；头像/立绘不能遮住字幕，按钮不能覆盖台词，整页不能横向溢出。
- 手机键盘弹起时可缩小/收起立绘，保障输入和发送；不强制横屏。
- 学习支持用侧栏或独立面板。展开时暂停演出，关闭后回到同一句、同一草稿；不反复挂载导致提示重新计数。
- 逐轮反馈完成后给轻量提示“本轮反馈已就绪”；学生主动查看，不用长反馈覆盖舞台。
- 历史包含完整已确认台词和用户发言，可复制文本；普通记录视图仍遵循仿真短回复规则。

### 4.4 打字机与播放控制

- `typing → line_ready → next_line / awaiting_input` 为本地播放状态；与网络状态、Attempt 状态分开。
- 默认 30 grapheme/秒，提供慢/标准/快/立即显示；句末停顿最多 250ms。用户可随时取消等待。
- 第一次按“下一句”在打字中先显示当前整句；第二次才推进。明确按钮标签随状态变化。
- Enter/Space 只在播放器自身拥有焦点时推进；输入框内不得截获回车、空格或中文输入法组合键。
- 收到消息后可先编辑草稿；仍在播放时点击发送，先完成本轮阅读确认，再按同一次明确意图发送一次，或者清晰提示先读完。MVP 默认采用“发送前先读完，文本保留”，不可暗中排队发出。
- 字素切分优先 `Intl.Segmenter`；不支持时整句显示，避免把 emoji、组合字符拆坏。依据：[MDN Intl.Segmenter](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/Segmenter)。
- 遵循 `prefers-reduced-motion`：取消字符动画、位移和呼吸效果；保留逐句手动推进。依据：[MDN reduced motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)。
- 屏幕阅读器按整句播报，禁止每字符触发 live region；完整当前句始终可获取。
- 定时器在卸载/跳过/换句时取消，隐藏标签页暂停；恢复不加速补播、不跳过未读内容。

## 5. 谈判态势：有因果的反馈，不做讨好积分

### 5.1 三个显示维度

| 维度 | 范围/初值 | 含义 | 明确不等同于 |
| --- | --- | --- | --- |
| 沟通信任 trust | 0–100，默认 50 | 信息一致、履约表述可靠、澄清误解等公开表达形成的估计 | 学生人格、礼貌用词数量、正式成绩 |
| 合作意愿 willingness | 0–100，默认 50 | 是否存在继续交换条件与讨论方案的空间 | 对手底价、一定成交、个人好感 |
| 条款共识 alignment | 按明确条款账本计算，初值通常 0 | 双方对本关待谈条款明确一致的程度 | 隐藏盈利空间、知识掌握程度 |

界面可用刻度条和档位“谨慎 / 平稳 / 积极”，默认不突出个位数的精确测量感。展开后可见数值、变化原因和原话。每局独立初始化，不把前一局对手的情绪带入下一局。

### 5.2 计算与防刷规则

- LLM 只提议观察事件；服务端按白名单、原话证据、置信度和版本化规则计算变化。
- 初版信任/合作按小幅增减；单维每轮总变化最多 ±8，最终 clamp 到 0–100。
- 同一事实/条款/事件重复出现不重复奖励。赞美、反复问候、同义复述不得无限加分。
- 礼貌但坚持有依据的还盘，可以提高信任，同时没有提高共识；多维度允许不同方向。
- 单方面大幅让步不能增加信任分；也不能自动视为高质量谈判。正式评价须检查学生的商业利益与策略。
- 态势更新失败时保留上一次已确认状态，显示“本轮态势暂未更新”，不显示假的 0 或随机数。
- 状态变化每轮至多播放一次；重连/重试/打开历史/重看简报不再次叠加。
- 学生可见数字只能来自公共互动证据。不得把对手私有成本、底线、BATNA、预算通过颜色/条形长度/“还差一点”反推出去。

### 5.3 态势怎样真正影响接下来的谈判

三个维度不只是装饰条。下一轮conversation输入最近已确认态势、公共解释与未决条款，并按以下规则生成行为：

| 当前状态 | 对手下一轮的优先行为 | 不允许的推导 |
| --- | --- | --- |
| trust 0–34（谨慎） | 优先澄清一个事实或要求说明依据；措辞专业 | 自动辱骂、无条件拒谈、提高报价惩罚学生 |
| trust 35–69（平稳） | 正常推进本轮目标 | 根据个位数变化机械换表情 |
| trust 70–100（信任较高） | 可减少重复核对、直接讨论具体交换 | 绕过价格底线或不再核实关键条款 |
| willingness 0–34（空间有限） | 点明当前障碍，提出一个替代或澄清问题 | 宣判学生失败、强制结束训练 |
| willingness 35–69（可讨论） | 讨论一个具体条件交换 | 无条件让步 |
| willingness 70–100（积极） | 优先推进尚未确认的条件，适时提议总结 | 自动成交或提前计算正式成绩 |
| alignment接近完成 | 聚焦剩余未决条款，核对关联条件 | 把有条件意向当正式接受 |

冲突时优先级：**关卡业务硬约束与学生利益边界 → 已确认事实/条款版本 → 当前教学目标 → 态势行为 → 表情动作。** 表情只是演出，不反向决定数值。执行者须用“相同公共历史、不同已确认态势”的fixture验证行为倾向有可见区别，同时保持相同业务边界。

### 5.4 条款共识与里程碑

- 代表关卡配置 2–4 个明确待谈条款，例如单价、数量/交换条件、交付条件。已固定且无需讨论的事实不充当白送进度。
- 条款有版本：`unaddressed / proposed / discussing / confirmed / reopened`。
- `confirmed` 必须引用双方对同一版本、同一数值/条件的明确接受；“可以考虑”只是 discussing。
- 数量/质量/付款等条件一改，受影响条款重新打开，不能保留旧版本的绿色确认。
- 初版 alignment = 已确认条款数 / 本关所需条款数 × 100；阶段顺序与不同条件的依赖写入关卡配置。
- 另设教学里程碑：说明还盘依据 → 提出互惠交换 → 明确下一步。来源于既有 checklist 与原话校验，可显示“1/3 项有证据”，不把它称为课程已完成。
- 允许达成模拟协议、合理暂缓、未达成。均由学生主动正式提交，正式评价成功后才按既有规则计入学习记录。
- 不设自动满分、自动提交、信任清零即强制失败；僵局提供一次复盘建议与继续/提交选择。

## 6. LLM 分工与短台词约束

### 6.1 保持三个用途

1. scenario：生成已有场景事实，以及仿真专用结构化公共简报与一次性短开场。
2. conversation：扮演对手；输出短台词及白名单内的表情、动作。不能输出最终成绩、UI 代码或直接控制态势分值。
3. evaluation：继续逐轮诊断、图谱推荐、正式评价；仿真额外输出带证据的态势事件候选。

不要新增“表情 Agent”“好感度 Agent”“导演 Agent”的额外常驻调用。分镜导演只是服务端规则与前端播放器。

### 6.2 每轮短回复

- 默认英文，1–3 个 speech beat，每个 1–24 个英文词，总计不超过 60 词；自然回答的常用目标 20–45 词。
- 每轮聚焦一个主要立场、一个条件或问题；包含必要商务信息，不为短而把 price/quantity/payment 截断。
- 禁止 From/To/Subject、完整函电署名、教学长评、重复复述全部背景。
- 必要台词按完整句生成；金额、百分比、日期、Incoterm 等事实必须经过语义/格式校验。
- 超长或格式错误：服务端做一次受约束的纠正重试；仍失败则明确失败并保留学生消息。不能截字、隐藏后半句、伪装成成功。
- 角色知道之前双方真实发言，不把旁白、学生未发送草稿、系统建议当成已经说过的话。

### 6.3 评价口径必须一起改

已有提示词检查函电格式，不能原样复用。新增仿真用逐轮/正式评价 profile，保留业务准确性、策略、目标达成、沟通质量；“完整”指本轮沟通任务所需信息，不要求每句话附称呼落款。

模式适用评价绑定到 Attempt 并在教师端说明；旧记录继续用旧版本。不要跨模式直接比较原始平均分并声称一种模式更好；至少保留筛选或模式标识。

## 7. 架构决策：一份真实对话，两种体验呈现

### 7.1 源数据与演出数据分开

- `Message.content` 保存全部合法短台词的规范文本，是历史、知识诊断、评价证据引用的真值。
- `SimulationTurnPresentation` 保存本轮的 beat 列表、表情动作、资产版本、消息关联与内容 hash。
- `SimulationBriefing` 是公共场景派生快照；不进入 messages。
- `SimulationStateSnapshot` 是服务器事件规则计算的快照；可由事件记录重放得到。
- 本地 `PlaybackCursor` 只保存读到哪一句、是否跳过，不修改 Message、状态或成绩。

详见 [契约文档](./01-contracts.md)。禁止维护另一套 AVG 聊天数据库导致教师看不到学生原话。

### 7.2 流式传输与打字机解耦

MVP 优先“服务端取得完整结构化回复 → 校验 → 事务保存 → 发出完整可播放事件 → 前端逐句打字机”。等待期间显示角色思考与明确加载提示。**不把 JSON token 直接流入对话框。**

保留 SSE 作为状态和结果传输通道，可先播已校验台词，再等待逐轮评价与态势。无需为追求表面实时性写半截 JSON 解析器。

SSE 是事件传输；浏览器断线并不天然保证 POST 请求幂等、服务端生成继续或事件持久化。本项目现有使用 fetch 读取流，要自行定义客户端重试与服务器状态恢复。依据：[MDN SSE](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)。

### 7.3 不引入大型游戏引擎

Vue 单文件组件 + CSS transform/opacity + 一个小型播放状态机即可。角色换表情与舞台进出使用 Vue Transition；不用逐帧 JS 改布局。依据：[Vue Transition](https://vuejs.org/guide/built-ins/transition.html)。

优先复用现有 API、鉴权、草稿、错误提示和正式提交流程。不得为了仿真重构所有 feature 或导入一个新的 UI 组件库。

## 9. 并发、恢复与一致性硬约束

1. 创建仿真 Attempt 支持 `Idempotency-Key`；相同用户/键/请求返回同一 Attempt；同键异请求 409。客户端在重试前保存该键，不能每次点击生成新键。
2. 同一 Attempt 同时最多一个未完成对话生成；多标签/并发请求由数据库条件更新或唯一约束保护，不靠单进程布尔锁。
3. 同一 `client_message_id` 携带不同 content 必须 409；相同请求只生成一个学生消息和一个对手回复。
4. 模型调用期间不用长时间持有数据库事务。先领取带期限的生成租约，完成后用 revision 校验原子提交；过期生成结果不得覆盖更新后的会话。
5. 台词与演出 payload 必须一起提交；不能 Message 成功而图像/分句随机重生成。
6. 对话完成和态势完成独立：即使逐轮分析失败，仍可读合法台词；允许继续时以最近确认状态为依据并提示待更新。后补事件只按轮次顺序重算，避免跳序加分。
7. 按 conversation revision 重放历史；旧客户端晚到的响应不得覆盖新状态。教师和学生 GET 得到同一版本的公共态势证据。
8. 生成中禁止提交；逐轮态势分析尚未完成时，提交可冻结已确认态势并标记缺失，不据此扣分。提交后禁止任何晚到回调改写冻结包。
9. 正式评价失败只重试评价，不重新生成台词或扣/加态势；重练创建新 Attempt。
10. 读历史、切换面板、重看分镜都是只读；不得再次记为学习行为、提示采用或得分事件。

## 10. 降级与失败体验

| 故障 | UI 行为 | 数据行为 |
| --- | --- | --- |
| 平静表情以外的图缺失 | 回退平静表情 | 记录资产错误，不影响训练 |
| 全部立绘缺失 | 中性占位形象 + 姓名 + 台词 | 不用其他身份角色替换 |
| 背景加载失败 | 纯色舞台 | 不阻止输入 |
| 模型返回非法表情/动作 | 白名单回退 neutral/none | 不执行模型给出的路径、脚本或 URL |
| 台词 JSON 无法校验 | “回复暂未完成，可重试” | 学生原话保留；同键重试 |
| 简报叙事失败 | 公共摘要模式 | 不重新生成场景事实、不泄露私有场景 |
| 台词成功、分析失败 | 台词继续可读，态势显示暂未更新 | 不伪造分析；可单独重试 |
| 播放中刷新 | 读服务端已保存内容，恢复最近句；无法定位则当前轮首句 | 不调 LLM，不重复状态事件 |
| 网络断开 | 保留草稿/待处理键，说明保存状态未知，恢复后 GET 对账 | 不根据前端动画结束认定成功 |
| 功能开关关闭 | 不允许新建仿真，旧仿真可只读回放或纯文本降级 | 保留历史、评价与提交记录 |

## 11. 资产规范与趣味表达

详细表格和 ImageGen 提示词见 [资产工单](./03-assets.md)。

默认资产规模：1 位对手，neutral/thinking/pleased/frustrated/confused 五种表情；none/nod/head_tilt 三个动作枚举；1 个背景；1 张头像。动作主要用固定立绘姿态或轻量变换，不做“5 表情 × 3 动作”的全量组合生图。

若用户提供的形象与现有 David Lim 身份明显不一致，先让用户选择保留角色身份或创建新的虚构商务角色。不能把头像换成另一种身份，却继续沿用旧姓名、公司、叙事和称谓。

愤怒/疑惑不由关键词机械触发；正常压价不等于冒犯。每轮默认至多一次明显表情/姿态切换，克制演出。平静也允许坚定拒绝，喜悦也不自动降价。

## 12. 性能与可访问性预算

- 不新增运行时生图调用；开局只加载本关背景、平静立绘、头像。其余表情空闲预载。
- 本关初始压缩图片总量目标 ≤ 2 MB，完整单角色包目标 ≤ 6 MB；若画质需要超过，记录实测理由再优化，不靠换低清图敷衍。
- 新增初始 JS gzip 预算目标 ≤ 40 KB；仿真采用路由/组件懒加载，不能把资产清单塞成大段 base64 进入主包。
- 点击“立即显示/下一句”在参考设备上视觉反馈目标 < 100ms；角色换图从缓存读取，不引起可见布局跳动。
- 代表测试设备上目标接近 60fps；记录 DevTools 性能截图/时间线。没有测量不能写“丝滑已验证”。
- LLM 端到端延迟单独记录至少 10 轮的首响应、台词就绪、评价就绪时间，报告中位数与慢样本；不能把动画播放时长当网络性能。
- 测 360×800、390×844、768×1024、1280×800；200% 缩放、长名字、长金额、英文断词、中文输入法、键盘聚焦、屏幕阅读顺序。
- 实测软键盘、Safari/iOS、Android Chrome 能测哪些就写哪些；浏览器改视口不代表实机软键盘验收。

## 13. 未来语音扩展：只保留必要接口

当前实现文本 Source of Truth 与 beat ID 即可。以后 TTS 通过 `(attempt_id, message_id, beat_id, voice_profile_version)` 获取音频；ASR 输出先成为可编辑草稿，学生确认后才走同一发送接口。

MVP 不创建空音频数据库表、不申请麦克风、不选择未经用户确认的语音供应商。以后接入时另开工单处理同意、音频保留期限、错误转写、打断、延迟、配额与字幕同步。

## 14. 分阶段开发总工单

### A · 基线与设计冻结

解决：防止把新模式侵入已验收系统。

- 读取当前 AGENTS、工作区差异、配置与测试；保护所有未提交的已有改动。创建自己的分支/补丁边界，禁止 git reset/clean 回退用户成果。
- 跑一次现有基线；失败先区分已有问题与本次问题，写入 `baseline.md`。
- 列出现有模型、路由、提示词版本、学生/教师读取链路和仿真接入点。
- 确认代表关卡 ID、先修测试夹具、角色资产依赖、feature flag 默认关闭。
- 将数据表、事件序列与模式绑定整理为简短 ADR；本文合理默认可直接采用，不每项等待批准。

验收：基线可复现、无改坏旧 IM、后续任务依赖清晰。

### B · 可独立验证的契约与规则

解决：先保证态势不是前端随机数。

- 新增严格 Schema、版本化 profile、消息/分镜不变量、态势纯函数、事件去重与条款版本规则。
- 写反例测试：重复恭维不刷分、合理拒绝不自动扣分、不同条件不能确认共识、私有数据不能被序列化。
- 暂不调用真实模型；固定 JSON fixtures 驱动。

验收：契约测试和规则测试通过，输入/输出示例与代码一致。

### C · 最小可交互舞台

解决：验证 AVG 阅读和输入是否顺手。

- Vue 实现背景/占位角色/头像/对话框/逐句播放/历史/速度/跳过。
- 测长句分页、Unicode、卸载清理、面板切换、草稿保留、减少动态效果。
- 手机优先验证输入区和按钮不被舞台挤掉。

验收：fixture 演示可实际操作、记录关键截图；明确尚未联调真实后端。

### D · 持久化、幂等与公共读取

解决：刷新、重试和教师回放可重复得到同一局。

- Alembic 新迁移，旧 Attempt 默认 chat，所有新表可加而不损旧数据。
- 仿真创建绑定、独立分镜快照、原子消息/分镜保存、状态事件和 revision。
- 新增仿真读取 API、状态重试 API、学生 ownership 与教师班级权限检查。
- 同步/流式发送入口统一派发，防止绕一个入口获得长回复或不同状态。

验收：迁移空库/旧库通过；同键异内容、并发、断线、权限测试通过。

### E · 三用途 LLM 与代表关卡

解决：得到真实、简短、情境一致的角色回应。

- 新增 scenario/conversation/round/final 仿真提示词及 profile，绑定新版本。
- 公共事实派生叙事、短台词结构校验、有限纠正重试；模型元数据与用量记录齐全。
- 评价标准适应简短商务交流；复用图谱推荐和教学诊断。
- 按既有 provider 统一调用，不直接在 route 或组件调供应商 SDK。

验收：mock 全闭环 + 可用时真实模型 ≥10 轮样本；没有格式泄漏、长邮件化或随意条款漂移。

### F · 学习支持、正式评价与教师证据

解决：趣味体验仍服务真实教学闭环。

- 仿真入口、简报、舞台、历史、草稿、图谱支持集成。
- 教师回放可见模式、原始完整短台词、分镜、状态变化与证据、正式评价版本。
- 正式冻结包含仿真相关版本与快照 hash；态势失败不会被当作零分。
- 以有先修的测试学生跑通新建 → 交锋 → 提示 → 提交 → 评价 → 教师回放。

验收：原 IM 回归不退化；新仿真记录通过同一课程进度与权限边界。

### G · 正式资产接入

解决：占位角色变成同一身份、一致构图的正式二次元资产。

- 收到用户底图后阅读可用 imagegen skill，通过 ImageGen 生成指定变体，保存原件和独立派生件。
- 按清单验证文件、尺寸、透明边缘、锚点、换表情脸部连续性、手机裁切及降级。
- 人工审美检查通过后将 asset pack 标记 approved；未提供底图时该阶段保持待资产，不阻塞其余代码工作。

验收：真实生成与视觉 QA 证据齐全，不能只验尺寸。

### H · 完整 QA、修复与交付

解决：不把“能运行”当作“可交付”。

- 执行 [全部 QA 矩阵](./02-qa-and-release.md)，修复失败并回归受影响范围。
- 最终代码冻结后跑格式、规范、类型、全量前后端测试、构建、文件行数、迁移与接口冒烟。
- 在真实 UI 完成至少一个仿真闭环和一个旧 IM 闭环，并执行失败恢复路径。
- 输出文件清单、API/数据库变化、真实测试统计、截图、性能记录、未解决项、开关/回滚方法和 5 分钟专家演示脚本。
- 只在全部必要验收通过时写“功能 MVP 完成”；正式图未到或模型未联调必须单列待办，不能以免责说明包装为全部完成。
