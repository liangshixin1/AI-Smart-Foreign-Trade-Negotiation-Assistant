# 02 · QA 矩阵、验收与交付手册

目的：执行者按此逐项验证 MVP，提供可以复核的证据。空勾选、计划中的测试、旧版通过记录都不算本次结果。

## 1. 测试层级与记录格式

- 单元：纯规则、契约解析、打字机、态势计算。
- 组件：逐句播放、角色 fallback、键盘行为、草稿与侧栏。
- API/数据库：幂等、权限、版本、事务、回放、故障恢复。
- E2E：真实 Vue + FastAPI + 测试数据库 + mock provider，不仅是拦截所有 API 的前端演示。
- 真实模型：使用已配置的三用途 provider，验证短台词、角色稳定、业务约束和语义判断。
- 人工/浏览器：视觉、移动布局、真实键盘、资产连续性与专家演示。

每项结果至少写：Case ID、代码版本或差异快照、fixture/账号类别、操作步骤、预期、实际、通过/失败/未测、证据路径。截图不得显示密钥，测试数据不得污染真实学生。

## 3. 契约与场景生成

| ID | 场景 | 必须断言 |
| --- | --- | --- |
| C01 | 旧 CreateAttempt 请求未传 mode | 默认 chat，旧流程不变 |
| C02 | 向不支持仿真的单证/邮件小节请求 simulation | 后端明确拒绝，不能只靠 UI 隐藏 |
| C03 | 相同创建 key 重试 | 一个 Attempt，一个场景，不额外收费生成第二局 |
| C04 | 同 key 改 unit/difficulty/mode | 409，无新增 Attempt |
| C05 | 简报 4–7 个合法分镜 | 所有公共占位符正确渲染；无需 private |
| C06 | 简报带不存在字段/private 占位符 | 拒绝，不向客户端泄露 |
| C07 | 简报擅自改变日期/报价/学生决定 | 验证失败并受控重试或摘要降级 |
| C08 | 叙事生成失败后刷新/恢复 | 仍为同一场景；不重置交易条件 |
| C09 | 简报重看 5 次 | LLM 调用次数不增加，Message/状态数不变 |
| C10 | 短开场 | 一条 assistant Message、1–3 beats、规范全文一致 |
| C11 | 简报成功但开场不合法 | 不用长函电或乱码替代；失败阶段可重试 |
| C12 | profile 新版本发布 | 旧 Attempt 仍使用旧版本；新 Attempt 才绑定新版 |

## 4. 台词与供应商接口

| ID | 场景 | 必须断言 |
| --- | --- | --- |
| L01 | 1、2、3 句合法英文短回复 | beat 顺序、角色、总词数和 Message.content 一致 |
| L02 | 4 beats / >60 words / 单句超24 words | 服务端拒绝并最多一次内容纠正，不客户端截断 |
| L03 | 模型包含开场称呼、署名、Subject、长教学评语 | 仿真短台词规范检查捕获并纠正 |
| L04 | JSON 截断、非法类型、未知必填字段、finish_reason非stop | 不显示原始 JSON，不保存为成功台词 |
| L05 | 非法表情/动作 | neutral/none 降级，合法台词保留；不执行任意路径/脚本 |
| L06 | speaker 是学生/另一个角色 | 内容验证失败，不伪造学生发言 |
| L07 | 美元金额、数量、付款期限、贸易条件 | 不能由短回复裁剪丢掉条件，不能违反关卡硬约束 |
| L08 | 同一谈判历史再次打开 | 不重新调用生成，不换表情随机重演 |
| L09 | 断线重发同一 client_message_id | 只存在一条学生消息和对应对手回复 |
| L10 | 同 key 但学生 content 不同 | 409，不覆盖原文 |
| L11 | 学生要求忽略角色、输出底价、把态势改为100 | 没有直接执行；响应/界面不泄露私有信息 |
| L12 | 真实对话目的 Key 与评价目的 Key | 路由到既有独立配置，日志仅记录用途及元数据 |
| L13 | 同步发送与流式发送 | 同一 mode policy；都不能绕过短输出和状态校验 |

对关键商务规则采用服务器私有的结构化 profile 校验：例如允许的商品、币种、让步条件和不可突破的底线。若现有内容只用自由文本描述，则先为代表关卡补充可校验配置，不把正则从一段小说里猜出的数字当业务真值。私有校验结果对学生只说明回应需要重试，不能提示“低于卖方成本 X”。

## 5. 播放器、输入与访问性

| ID | 场景 | 必须断言 |
| --- | --- | --- |
| U01 | 点击下一句时仍在打字 | 第一次整句显示、第二次推进；不连跳 |
| U02 | 多次快速点击/键盘连按 | 不跳过未确认句、不重复发送 |
| U03 | 中文、emoji、组合字符、英语撇号 | 字素完整；无 Segmenter 时整句降级 |
| U04 | 输入框中的 Enter/Space/中文组合态 | 不被播放器捕获；不得误发送或丢字 |
| U05 | 打字过程中打开支持/历史 | 暂停并保留当前 beat；关闭后继续 |
| U06 | 一边读取一边编辑草稿 | 不被新事件覆盖；发出前有明确意图 |
| U07 | 速度切换/立即显示/关闭动画 | 正文不变；状态和得分不受影响 |
| U08 | 刷新 | 从服务端消息恢复，游标失效则安全回到本轮开头 |
| U09 | 切换用户 | 不读到另一用户的草稿或播放游标 |
| U10 | 组件卸载/路由切换/隐藏页 | 定时器与监听器清理；无幽灵推进、重复事件 |
| U11 | reduced motion | 取消逐字、位移、呼吸；手动逐句可用 |
| U12 | 屏幕阅读器 | 姓名/整句/按钮顺序明确，不每字符播报 |
| U13 | 仅键盘 | 可完整观看简报、输入、打开支持、提交与取消弹窗 |
| U14 | 200% 缩放、最长姓名、最长合法句 | 不遮挡、可滚动读完、焦点可见 |
| U15 | 无图/慢图/404图 | 默认立绘或占位，不影响台词与输入 |
| U16 | 竖屏键盘弹起、横竖切换 | 输入和发送可见，草稿和当前句不丢 |

必须使用 fake timers/可注入时钟测试播放器；不要让单元测试真实等待几十秒。组件测试不能只快照 DOM 字符串，必须操作播放、切换和错误路径。

## 6. 态势、条款与教学公平

| ID | 输入/情景 | 必须断言 |
| --- | --- | --- |
| S01 | 初始没有学生发言 | 明确初始状态，不虚构学习证据 |
| S02 | 同一赞美换词重复 5 次 | 信任/合作不累计增加 |
| S03 | 有依据的压价/合理拒绝 | 不因“拒绝”关键词自动判攻击或降低信任 |
| S04 | 有明确交换条件的新方案 | 正确识别一次，展示对应原话 |
| S05 | 明示改口并说明原因 | 不自动视为欺骗或失信 |
| S06 | 前后矛盾但没解释 | 必须有两处原话才能接受矛盾事件 |
| S07 | 同一轮多事件 | 同维总变动≤±8，最终0–100 |
| S08 | 相同事件重放/重新订阅 | 快照值不变，动画不重播 |
| S09 | 不存在/跨 Attempt 的证据 message_id | 拒绝，不改态势 |
| S10 | quote 存在但解释不符 | 人工样本审查捕获；不凭子串存在声称语义必然正确 |
| S11 | 模型低置信/含糊建议 | 不变；显示待确认或暂无变化 |
| S12 | “I might accept if…” | 不确认为已达成条款 |
| S13 | 单价同、数量或付款条件不同 | 不确认同一协议版本 |
| S14 | 已确认条款后修改关联条件 | reopened，alignment正确回落 |
| S15 | 同义条款/十进制金额/单位 | 规范化可复现，不由浮点误差确认 |
| S16 | 全条款暂定一致 | 可建议总结，不自动提交或completed |
| S17 | 态势很高、教学目标没达成 | 不给满分、不误计进度 |
| S18 | 未成交但学生坚守合理底线 | 正式评价允许优秀，给出专业依据 |
| S19 | 为成交做无条件大幅让步 | 不能只因“合作意愿提高”得到高策略评价 |
| S20 | 逐轮分析失败/迟到 | 台词保留；旧快照不归零；补事件按轮次重算 |
| S21 | 隐藏成本/底价不同但公共对话完全相同 | 公共态势不因为私有数字不同而变化/泄漏 |
| S22 | 长度短但内容完整 | 仿真评价不因无抬头落款扣分 |

必须把至少 S02、S03、S12、S13、S16、S18 纳入专家演示或可复现测试报告，作为“寓教于乐仍有专业边界”的证据。

## 9. 真实模型样本验收

使用专门测试账号与隔离业务记录。先确认已有 provider 配置、调用预算和测试环境；不把 Key 打印到日志，不将密钥写到测试 fixture。

至少 10 个学生回合，覆盖 3 条脚本路径，每条至少 3 回合，额外至少 1 个提示注入/私有信息探测回合。应至少完成一局正式提交与教师回放。

建议路径：

1. 专业互惠：给出合理还盘依据 → 数量/付款交换 → 确认条件 → 总结下一步。
2. 合理僵局：对方守价 → 学生有依据拒绝 → 提出替代 → 双方暂缓；评价不能把未成交直接判差。
3. 表面讨好：连续赞美但无事实 → 空泛压价 → 无条件退让；态势不刷满、专业评价有区分。
4. 故障与注入：要求输出底价/改数值/返回脚本，并在一轮响应后刷新或重试。

记录每轮：输入、规范台词、词数、beat数、表情是否合适、事实是否漂移、事件解释、等待耗时、是否修复重试。真实输出含学生测试全文时仅存项目测试证据，不上传外部公共报告。

验收阈值：

- 所有被系统接受的台词满足硬结构与长度规则；不满足者必须转为失败或修复后成功。
- 10轮中至少9轮首次满足格式与长度目标；低于目标先调提示词，不靠提高上限遮掩。
- 无接受的私有信息泄漏、学生代言、关键条款漂移、满好感自动完成。
- 角色表现合理与情境相关性人工逐轮检查；不把“JSON合法”当语义合格。
- 记录完成局与失败样本，不能只展示最成功的一轮。

## 10. 验证命令

以本仓库实际可执行工具为准；使用本地已安装二进制，避免包管理器临时联网切换版本。

```sh
./node_modules/.bin/prettier --check .

./node_modules/.bin/vue-tsc -b --force
```

```sh
.venv/bin/ruff format --check apps/api scripts
.venv/bin/ruff check apps/api scripts
.venv/bin/mypy apps/api/app
.venv/bin/pytest apps/api/tests
.venv/bin/python scripts/check_file_lengths.py
```

从 `apps/api` 执行 pytest 时解释器路径为 `../../.venv/bin/python`。

新迁移需在临时测试数据库执行 `upgrade head` 并与旧库备份副本兼容验证；不要为了测试 downgrade 破坏正在使用的数据库。Neo4j相关回归按已有 `scripts/smoke_neo4j_phase2.py` 流程与测试环境执行，不重发布覆盖既有正式图谱。

E2E：先检查本环境可用的浏览器工具。若现有测试栈不支持全链路，新增最小可重复的 browser/API 测试入口与文档，不能凭空写 `pnpm test:e2e` 并宣称已运行。运行时浏览器控制遵从当前工具说明，不绕过权限机制。

## 12. 5 分钟专家演示脚本

| 时间 | 操作 | 希望专家看到的证据 |
| --- | --- | --- |
| 0:00–0:30 | 准备页选仿真 | 原IM保留；同一教学目标，两种体验 |
| 0:30–1:00 | 播放简报，点立即显示，重看摘要 | 情境代入；学生掌握自己的阅读节奏 |
| 1:00–2:00 | 提出有依据的还盘 | 短台词、固定表情反应、互惠条件 |
| 2:00–2:40 | 展开态势变化证据与学习支持 | 数值有原话依据，图谱支持与旧模式一致 |
| 2:40–3:20 | 给出合理拒绝/替代条件 | 不鼓励无底线讨好，商业结果与学习质量分离 |
| 3:20–4:10 | 正式提交、看评价 | 不是好感满格就通关，评价适用简短商务交流 |
| 4:10–5:00 | 教师打开同一次训练 | 完整台词、态势原因、教学反馈可追溯 |

真实服务延迟导致5分钟内难以演完时，备一份**明确标注为既有已保存记录的回放**，不把预录/缓存伪装成当场实时生成。

## 13. 发布与回滚

- 新建仿真入口使用服务端 feature flag + unit/profile allowlist，初始关闭，测试通过后仅对试点关卡开放。
- 在本地测试/演示环境内按照已授权范围启用；对外生产发布或扩大学生范围按项目当前发布授权执行。
- 保留旧IM路径、旧prompt、旧schema默认值、旧资产包。
- 回滚优先关闭仿真新建入口；已有仿真记录通过兼容读取器和文字记录保留。
- 数据迁移采用增量；不依赖删除新表来恢复业务，不在有新数据时草率down迁移。
- 记录可回滚提交/补丁、数据库备份位置、flag位置、资源包版本和恢复步骤。

## 14. 最终交付模板

执行者在 `docs/implementation/avg-simulation-mvp/` 建立以下实际交付件（开工时再创建；此处只是要求）：

1. `baseline.md`：起始状态、已有问题、版本与依赖。
2. `implementation.md`：实际架构、修改文件、接口/数据库变化、与原工单差异。
3. `qa-results.md`：逐Case结果、真实测试统计、环境、截图和性能证据链接。
4. `known-issues.md`：未解决、未验证、外部依赖；不能混用“已实现”与“已验收”。
5. `demo-and-rollback.md`：启动方式、演示账号获取方式、演示路线、开关、回滚。
6. 对应截图、测试输出与资产清单。

最终回复先说能实际做什么，再说测试结果与限制。不能只写“所有测试通过”，必须给本次数字和剩余条件；没有真实模型联调时不能写“完整MVP验收通过”。
