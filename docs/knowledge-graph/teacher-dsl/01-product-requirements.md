# 产品需求：教师教学案例 DSL 与知识图谱编译

## 1. 用户问题

现有知识图谱模型可以表达复杂教学关系，但若让一线教师直接维护节点表、关系表和图数据库字段，系统将难以推广。产品需要把图谱复杂性封装为教师可理解的教学案例设计流程，同时保留科研所需的语义结构、版本性和可追溯性。

## 2. 产品目标

教师能在不理解图数据库的前提下，用一份 Excel 完成案例设计；系统能把案例稳定地编译成知识图谱草稿；课程专家和技术员能解释、修正、审核、发布和回滚；学生训练与教师学情分析能真正消费这些关系。

首个可演示闭环：

1. 教师下载模板并填写或修改一个案例。
2. 上传后获得按“工作表—行—字段”定位的校验结果。
3. 系统生成教学结构预览和图谱变更草稿。
4. 技术员/专家查看新增、复用、冲突和低置信度项。
5. 审核通过后发布为指定课程版本。
6. 学生训练能获得与局面相关的知识、策略和分级提示。
7. 教师能看到学生在哪类局面、策略和评价维度上薄弱。

## 3. 角色与权限

| 角色 | 主要任务 | 允许操作 | 明确禁止 |
|---|---|---|---|
| 任课教师 | 设计与修改教学案例 | 下载模板、上传草稿、查看校验、提交评审 | 直接编辑图谱关系、直接发布 |
| 课程专家 | 保证教学与专业质量 | 审核案例、确认概念复用或新建、修改教学语义 | 绕过版本和审计 |
| 技术员 | 维护编译规则和图谱运行 | 管理词表、映射规则、冲突、发布与回滚 | 修改教师原始文件而不留痕 |
| 学生 | 完成训练并使用脚手架 | 获取与当前局面相关的资源、提示和反馈 | 浏览未授权全量图谱 |
| 系统 | 解析、校验、编译和记录 | 生成草稿、计算置信度、保留来源 | 让 LLM 自动批准或直接写入已发布图谱 |

## 4. 教师教学案例 DSL

DSL 由七类教学概念构成，均用自然教学语言表达：

| 教学概念 | 教师回答的问题 | 系统内部可推导结构 |
|---|---|---|
| 案例 | 学生扮演谁、面对谁、要完成什么 | Scenario、Role、Goal、Context |
| 关键局面 | 学生会看到什么，应识别什么 | Phenomenon、PhenomenonType、Cue、Risk |
| 应对策略 | 在什么条件下做什么，避免什么 | Strategy、Tactic、Applicability |
| 知识与材料 | 做决定需要哪些知识或文件 | Terminology、Rule、DocumentKnowledge、Resource |
| 分级提示 | 学生卡住时如何逐步帮助并撤除 | Scaffold、Trigger、Level、WithdrawalCondition |
| 评价量规 | 看什么证据，什么叫达标或优秀 | RubricDimension、Competency、EvidenceRule |
| 结果与复盘 | 不同做法可能带来什么结果 | NegotiationOutcome、OutcomeCondition、Reflection |

教师表格不出现节点标签、关系类型、Cypher、Neo4j 属性名、UUID、向量字段或发布数据库字段。

## 5. 功能需求

### 5.1 模板与填写

- 提供带说明、示例、下拉选项和自动检查的 `.xlsx` 模板。
- 一个工作簿可以包含多个案例；教师使用“案例编号”和“局面编号”进行跨表引用。
- 所有必填项、允许值、长度限制和权重要求在模板内可见。
- 教师可以删除示例后填写，也可以复制案例行继续设计。
- 模板版本必须写入文件元数据或说明页，上传时校验兼容性。

### 5.2 上传与校验

- 校验文件格式、模板版本、必填项、重复编号、跨表引用、评价权重、提示撤除条件和结果触发条件。
- 错误信息必须定位到工作表、行、列，并使用教师语言说明如何修复。
- 错误分为阻断、警告和建议；只有阻断项会禁止提交评审。
- 同一文件重复上传具备幂等性，不得生成重复草稿。

### 5.3 自动映射与预览

- 将教师表述规范化为内部语义对象，并优先复用已审定词表。
- 系统展示“案例教学结构预览”，先展示教学逻辑，再提供专家图谱视图。
- 每项映射显示来源、处理方式、置信度和是否需要人工确认。
- 新概念、同名异义、近义重复、跨课程冲突进入专家审核队列。
- 自动关系来自确定性规则或经版本化的映射规则；LLM 只能提供候选。

### 5.4 专家审核与发布

- 审核页展示新增、复用、修改、删除、冲突和影响范围。
- 专家可合并别名、创建新概念、修改类型、退回教师或接受建议。
- 每次发布绑定课程版本、模板版本、编译器版本、审核人和变更集。
- 已发布版本不可原地覆盖；支持从上一版本回滚。

### 5.5 教学消费

- 场景生成可读取案例背景、关键局面与约束，但不得把答案泄露给学生。
- 对话 Agent 可依据局面触发规则呈现现象，并根据学生策略推进不同结果。
- 评价 Agent 可按量规识别证据，并将薄弱项关联到局面、策略或知识资源。
- 脚手架按触发条件分级提供，并记录使用次数与撤除情况。
- 教师端聚合“学生在哪类局面识别失败、策略选错、知识误用、需高级提示”。

## 6. 非功能需求

- 可解释：所有生成关系可追溯到教师原始单元格或审定词表。
- 安全：教师文件隔离存储，禁止执行公式宏和外部链接；敏感字段不进入日志。
- 稳定：单个工作簿建议不超过 100 个案例；上传、校验和编译均异步可重试。
- 一致：发布时 PostgreSQL 元数据与 Neo4j 图谱采用同一变更集编号。
- 可回滚：失败时不得留下半发布状态；支持撤销到上一稳定图谱版本。
- 可测试：解析、校验、映射、差异计算和发布均有独立自动化测试。
- 可维护：映射规则、词表和模板版本均配置化，不与路由或提示词混写。

## 7. 范围控制

### P0

- 教师模板、四类示例、上传校验、教学结构预览。
- 确定性映射、审定词表复用、草稿变更集。
- 专家审核、发布、回滚和审计。
- 至少一个训练关卡消费图谱生成的提示与评价映射。

### P1

- 浏览器内案例编辑器、Excel 往返导出。
- 别名推荐、重复概念聚类、跨案例复用建议。
- 教师学情聚合与薄弱点到教学资源的闭环推荐。

### P2

- 大规模教材抽取、复杂 RAG、多模态图谱、自动本体演化。
- 面向学生的自由探索大图与高级三维可视化。

## 8. 验收标准

- 3 名未接触 Neo4j 的任课教师中至少 2 名能在 30 分钟内完成一个案例草稿。
- 教师模板可见字段中不出现 Neo4j、Cypher、节点标签、关系类型或内部 UUID。
- 100% 阻断错误能定位到工作表、行和字段。
- 同一文件重复上传不产生重复实体或关系。
- 每个发布关系都能回溯到教师单元格、审定词表或人工审核决定。
- LLM 候选未经人工确认不得进入已发布图谱。
- 发布失败自动回滚；上一稳定版本仍可供训练使用。
- 演示关卡能根据局面提供至少两级提示，并在评价中返回关联的能力薄弱点。
