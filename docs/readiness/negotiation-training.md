# 谈判训练闭环就绪报告

## 结论

当前版本已达到学生、教师、技术员三端内测条件，可以冻结谈判训练主线并转入知识图谱的边界设计。这里的“就绪”指核心教学闭环真实可操作、失败可恢复、证据可追溯；不代表异步任务队列、`.xlsx` 直传或教师布置任务等后续增强已经完成。

## 已验收范围

- 所提供 `levels.py` 的 9 个流程、20 个关卡已全部迁移，运行时不依赖旧 Python 文件。
- 每关独立保存场景、角色脚本、形成性评价和正式评价提示词；课程版本不可原地覆盖。
- 三个 Agent 使用独立 Key；场景生成一次后保存快照，对话使用 SSE，逐轮评价返回分数、Pros、Cons、详细评价和下一步建议。
- 正式提交冻结消息和版本绑定；评价证据只能绑定真实学生消息，证据引用由服务端校验并精确落库。
- 学生草稿可恢复、训练历史可回看、评价失败可重试、已完成训练可创建关联重练。
- 教师可管理名册、批量导入 CSV、筛选学生、查看明确风险规则、结构化薄弱能力、趋势和完整回放。
- 技术员可配置并分别测试三个 Agent，Key 不回显；根目录 `.env` 为优先生效的本地主配置文件。

## 真实 DeepSeek 证据（2026-07-16）

先以课程 `2.0.0-beta.20` 的前两关验证失败恢复，再对最终课程 `2.0.1-beta.20` 执行完整真实调用：

- 场景、对话、逐轮评价、正式评价均由 `deepseek-v4-flash` 返回，调用记录状态为 `completed`。
- 流式链路出现 `message.started`、`message.delta`、`message.completed`、`round_evaluation.started`、`round_evaluation.completed`、`stream.closed`。
- 第一关首次正式评价因模型改写证据引用被 Schema/证据校验拒绝，Submission 未丢失；修正证据绑定后从 `evaluation_failed` 重试成功。
- 第二关从新建 Attempt 到教师回放一次完成，正式分数 56.5，教师完成记录同步增加。
- 最终版本 `2.0.1-beta.20` 再次从零通过四次 Agent 调用，正式分数 48.5，教师总览和回放均显示 completed。
- 浏览器验收实际显示 9 章 20 关、学生历史与进度、教师风险筛选、共性薄弱维度和个人能力趋势。

## 转入知识图谱前的边界

知识图谱不得改变 Attempt 状态机、正式进度判定、评价证据或课程版本规则。首个图谱切片应只提供“知识标签—课程单元—评价维度—证据”的只读关联与教师查看入口；图谱不可直接决定权限、完成状态或分数。复杂 RAG、教材自动拆图和 Neo4j 管理后台仍应分阶段进入。
