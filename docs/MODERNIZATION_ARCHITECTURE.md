# 渐进式现代化重构说明

## 为什么不直接推倒重写

现有系统已经覆盖谈判训练、教师管理、知识图谱、语音和 AI 服务。一次性重写会让需求冻结、回归范围和上线风险同时失控。本次采用“绞杀者模式”：新架构与旧系统并行，按照业务域逐步迁移。

## 后端边界

`negotiation_assistant` 是新的应用内核，仅负责装配：

1. `config.py`：类型化配置，业务代码不再散落读取环境变量。
2. `application.py`：可测试的 Flask 应用工厂。
3. `blueprints.py`：集中登记路由模块。
4. `bootstrap.py`：隔离数据库、Neo4j 和知识索引启动任务，并记录降级状态。
5. `web.py`：旧版/新版前端入口和健康检查。
6. `errors.py`：统一框架错误格式。

现有 `routes`、`services`、`models` 暂时保持兼容。后续应以“一个业务域一次 PR”为单位，将服务迁入对应领域包，而不是继续扩大公共模块。

## 前端边界

React 工程采用按功能组织，而不是把所有逻辑放入单个 `App.tsx`：

- `app`：应用装配；
- `features`：业务功能与状态；
- `services`：API 类型和网络适配；
- `components`：可复用展示组件。

生产构建部署到 `/modern/`，旧版入口保留在 `/`。当某个业务域完成迁移后，再把旧入口的对应导航切换到 React 页面。

## 中文注释原则

注释用于解释“为什么这样设计”、外部依赖降级策略和不明显的业务约束；不逐行翻译代码。公共模块、复杂流程和兼容层需要中文文档字符串，简单赋值和直观 JSX 不添加噪声注释。

## 后续拆分顺序

1. 认证与用户上下文：建立统一 API 客户端和权限边界。
2. 场景与谈判会话：从学生端巨型脚本迁出核心训练链路。
3. 课程、作业与学生分析：形成独立教学管理域。
4. 知识图谱与导入：拆分查询、命令、导入任务和 Neo4j 仓储。
5. 清理旧静态文件及 `database.py` 巨型持久层，按领域建立仓储。

每次迁移必须包含契约测试，并在删除旧实现前完成新旧接口的等价验证。
